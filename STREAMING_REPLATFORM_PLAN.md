# Streaming Re-platform Plan — consensus_polling (AI Supreme Court)

Generated by /plan-eng-review on 2026-06-22.
**Supersedes `DEPLOY_REPLATFORM_PLAN.md` (Fargate cleanup) and the poll-chunked
syllabus in `RESPONSE_SYNTHESIS_PLAN.md`.** Both collapse into the stream.

## The pivot

Move to **strictly Lambda + full token streaming for all 9 justices**, custom
domain `scotus.me`. The eureka: the background-thread async-job model is the only
reason Lambda was wrong before. Streaming deletes that model — one invocation
holds the connection open and streams until done — so Lambda becomes the *simpler*
fit, not the harder one. The fragile machinery (daemon thread, `ThreadPoolExecutor`,
DynamoDB `job_progress` polling, and the "in-flight job lost on redeploy" failure)
all gets removed, not migrated.

## Locked decisions

| # | Decision | Choice |
|---|----------|--------|
| Compute | Platform | **Lambda response streaming** (replaces Fargate) |
| Front door | Transport | **CloudFront → Function URL (OAC)** — ALB can't stream Lambda |
| Domain | Hostname | **`scotus.me`**, ACM cert in **us-east-1** (CloudFront requirement) |
| Framework | App | **Quart** (async Flask) + **AsyncOpenAI** |
| Concurrency | 9 streams | `asyncio` tasks → `asyncio.Queue` → multiplexed output stream |
| Packaging | Lambda | **zip + Lambda Web Adapter layer** (faster cold start than container) |
| Synthesis | Grounding | **Code computes the tally; LLM writes only prose** (unchanged from CEO review) |
| Synthesis | Single judge | N=1 → plain-English TL;DR; N≥2 → consensus syllabus |
| Certainty/Scope | Axes | Parse line 2, stream as labels + feed the syllabus |
| IaC | Tool | **CDK Python**, Nigel-shape `infra/` + `aws/` + `admin/` (carried from the retired deploy plan, retargeted to Lambda) |
| Data | DynamoDB | Fresh tables, parameterized names; durable log written after the stream |

## Target architecture

```
Browser  (fetch + ReadableStream reader → 9 judge panels + syllabus)
   │  one request, held open
   ▼
Route53 (scotus.me) → CloudFront (ACM us-east-1, OAC) → Lambda Function URL
                                                         (InvokeMode: RESPONSE_STREAM)
   │  Lambda Web Adapter → Quart app
   ▼
async handler = streaming generator:
   1. rate-limit check (DynamoDB GSI on ip_address) → 429 before opening stream
   2. fan out 9 × AsyncOpenAI responses.create(stream=True), file_search per judge
   3. asyncio tasks push (judge, token) → asyncio.Queue
   4. generator yields tagged chunks → client routes each to its judge panel
   5. per-judge stream error → emit {judge, error} chunk, others continue
   6. on all 9 done → parse outcomes + Certainty/Scope → compute tally IN CODE
   7. stream the syllabus (grounded: tally is a fixed input, LLM writes prose)
   8. finally: write queries / responses / syllabus to DynamoDB (durable even on
      client disconnect)
   ── no daemon thread, no job_progress, no polling, no 30s timeout, no redeploy-loss
```

## Failure modes

| Codepath | Failure | Handled how | User sees |
|----------|---------|-------------|-----------|
| One judge's stream | API error / timeout mid-stream | per-judge `{error}` chunk; other 8 continue | that panel shows an error, rest stream fine |
| Synthesis stream | error after the 9 | emit `{syllabus_error}`; the 9 answers + vote bar already rendered | full results, no syllabus headline (additive) |
| Client disconnect | user closes tab mid-stream | `finally` writes whatever completed to DynamoDB | query still logged |
| Grounding | LLM tries to miscount | **can't** — tally is code-computed, passed as fixed input | always-correct count |
| Certainty/Scope parse | model omits line 2 | parser returns `None`, label hidden | card without that label |
| Cold start | first request after idle | zip + Web Adapter ≈ ~0.5-1.5s; show a connecting state | brief connect, then tokens |
| Rate limit | >5/IP | DynamoDB GSI lookup → 429 before stream opens | "limit reached" message |

No silent failures: every degraded path is visible and the user still gets whatever streamed.

## Migration (parallel + cutover, reversible)

```
1. Build infra/ CDK: Lambda (zip + Web Adapter) + Function URL + CloudFront +
   ACM(us-east-1, scotus.me) + Route53 + fresh DynamoDB tables (+ GSI on ip_address).
2. Rewrite app → Quart streaming generator; rewrite frontend → stream reader.
3. Deploy NEW stack; smoke via the Function URL directly (bypass CloudFront).
4. Create Route53 hosted zone for scotus.me; point registrar nameservers at it.
5. ACM DNS-validates; CloudFront alias scotus.me; verify HTTPS + streaming end-to-end.
6. Tear down the OLD Fargate stack (ECS/ALB/API GW/old tables/IAM). Don't recreate
   the dead DocumentDB policy.
── Rollback before step 6 = leave the old Fargate stack serving; don't flip DNS.
```

## Setup prerequisites (one-time, operator)

- ACM cert for `scotus.me` MUST be in **us-east-1** (CloudFront).

## NOT in scope

- Resumable streams across client disconnect (write-as-you-go covers durability; resume is overkill).
- Prompt-caching the per-judge file_search context (revisit if cost grows).
- Confidence-weighting the verdict by Certainty (the real Court doesn't weight votes).
