# AI Supreme Court

An experimental research platform that simulates how the nine current U.S.
Supreme Court Justices might reason about a constitutional question.

You ask a yes/no constitutional question. Nine AI "justices" — each grounded via
RAG in that justice's own written opinions — answer independently and in
parallel. The app classifies each answer (Support / Overturn / Remand, plus
Certainty and Scope axes), tallies the vote in code, and streams a plain-English
**syllabus** synthesizing the ruling. Everything streams token-by-token.

Live at **[scotus.run](https://scotus.run)**.

## How it works

```
Browser (static/script.js)  ── POST /api/query ──►  Quart ASGI app (app.py)
                                                          │
                                    ┌─────────────────────┴──────────────────┐
                                    ▼                                        ▼
                        9 × OpenAI Responses API                    DynamoDB
                        (file_search over a per-judge               (query history,
                         vector store of real opinions)              vote counters)
                                    │
                                    ▼
                        NDJSON stream ──► classify ──► tally ──► syllabus
```

Each justice gets a dedicated OpenAI vector store built from their real
opinions and the corresponding case syllabi. Answers are retrieved-augmented,
then classified and synthesized.

For the full design — request flow, streaming model, infrastructure, security —
see **[ARCHITECTURE.md](ARCHITECTURE.md)**.

## Quick start (local)

Requires Python 3.12 and an OpenAI API key.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

echo "OPENAI_API_KEY=sk-..." > .env      # gitignored

# One-time: build a vector store per justice from scotus/data/.
# This makes many OpenAI API calls and will incur cost.
python scotus/initialize_judges.py

./run.sh                                  # http://localhost:8080
```

Tests:

```bash
pip install -r requirements-dev.txt
pytest
```

> **Note on cost.** Initialization uploads the full opinion corpus to OpenAI and
> creates nine vector stores. Each query fans out to nine `gpt-5` calls. Check
> current OpenAI pricing before running this at any volume.

## Deploying

The production stack is AWS CDK: CloudFront → Lambda Function URL (response
streaming) → Quart under the Lambda Web Adapter, with Route53 + ACM.

- **[docs/deploy.md](docs/deploy.md)** — step-by-step deploy commands
- **[infra/README.md](infra/README.md)** — stack layout and CDK details
- **[aws/](aws/)** — operational scripts (`create.sh`, `redeploy.sh`, `status.sh`, …)

If you fork this, the domain `scotus.run` is hardcoded in
`infra/scotus_stack.py` and `infra/app.py` — change it to your own before
deploying.

## Data and assets

- **Opinion corpus** (`scotus/data/`) — scraped from
  [Justia](https://supreme.justia.com) (see `scotus/index.json` for the source
  index, and `scotus/SCRAPER_README.md` for the scraper). The opinion text
  itself consists of U.S. federal government works in the public domain. The
  MIT license below covers this project's *code*, not this third-party data.
- **Justice portraits** (`static/images/*.jpg`) — the official Supreme Court
  portraits, public-domain federal works, mirrored from Wikimedia Commons. The
  source URLs are in `app.py` and are also used as runtime fallbacks.
