## Goal

Kill the ~550 lines of imperative bash deployment, adopt the Nigel repo shape
(`infra/` IaC + `aws/` op-scripts + `admin/` data-scripts), and right-size the
running service — **without changing the compute platform** (staying on ECS
Fargate, so the Flask app and its threading model are untouched).

## Locked decisions

| # | Decision | Choice |
|---|----------|--------|
| Compute | Platform | **Stay on ECS Fargate** (no App Runner / Lambda / external PaaS) |
| IaC | Tool | **AWS CDK in Python**, single stack `ScotusStack`, in `infra/` |
| Front door | Topology | **ALB + ACM (HTTPS) + Route53**, drop API Gateway. `APP_DOMAIN` is config |
| Data | DynamoDB | **Create fresh tables, abandon old history.** Names parameterized via `TABLE_PREFIX` |
| Secrets | Store | **Keep SSM Parameter Store** SecureString (free, app already reads it) |
| Migration | Strategy | **Parallel stack + DNS cutover**, tear down old stack after verify |
| Cleanup | Legacy files | **Delete all** (11 scripts, SQLite, committed logs, stale README) |
| Reliability | Async job loss on redeploy | **Accept + document** (no staleness guard) |
| Tests | Scope | **Regression test only** (table-name env) + `cdk synth`; rest → TODO |
| Sizing | Fargate task | **512 CPU / 1024 MB, gunicorn 2 workers** (down from 1024/2048, 4 workers) |

## Target architecture

```
Route53  (APP_DOMAIN, e.g. scotus.nigel.bot)
   │  A/ALIAS → ALB
   ▼
ALB :443 HTTPS (ACM cert)  ──health: /health──►  ECS Fargate service
                                                   512 CPU / 1024 MB, 24/7 (desired=1)
                                                   │ slim Docker image (ECR)
                                                   │ gunicorn 2 workers × 2 threads
                                                   │ Flask app.py  (LOGIC UNCHANGED)
                                                   │  └─ ThreadPoolExecutor(9) per multi-judge job
                                                   ▼
                       DynamoDB (fresh): ${PREFIX}Queries / ${PREFIX}Responses / ${PREFIX}JobProgress(TTL)
                       SSM Param Store: /scotus/openai-api-key → injected as OPENAI_API_KEY
                       CloudWatch Logs: /ecs/scotus
   app ──► OpenAI Responses API (per-judge file_search vector store, reasoning=medium)

  Defined entirely in:  infra/  (CDK Python, ScotusStack)
  Operated via:         aws/    (create/redeploy/status/logs/start/stop/destroy)
  Data/judge admin:     admin/  (init_judges / delete_judges / query_history)
```

Removed vs today: API Gateway hop, ALB-less public Fargate exposure, the dead
DocumentDB IAM policy, and the 30s API-Gateway timeout that could 504 slow
single-judge queries.

## Migration runbook (parallel + cutover — reversible, zero-downtime)

```
1. Author infra/ ScotusStack with NEW table names (TABLE_PREFIX=Scotus →
   ScotusQueries/ScotusResponses/ScotusJobProgress), new ECS service + ALB +
   ACM + log group. No collision with the live old stack.
2. Parameterize dynamodb_util.py table names; add regression test; tighten
   .dockerignore; gunicorn 4→2 workers.
3. aws/create.sh: initialize_judges.py (regenerate judge_assistants.json)
   → docker build/push → cdk bootstrap → cdk deploy.
4. Smoke the NEW stack via its ALB DNS directly (before DNS cutover):
     /health → {healthy, judges_loaded: 9}
     single-judge /api/query → outcome returned
     multi-judge /api/query → job_id → /api/progress → completed + summary
     /api/total-queries → responds
5. ACM cert DNS-validates (CDK auto-writes the Route53 record); then point
   Route53 APP_DOMAIN A/ALIAS at the new ALB. Lower the record TTL first.
6. Verify HTTPS on APP_DOMAIN end-to-end.
7. Decommission old: delete old ECS service/cluster, ALB, API Gateway, old
   DynamoDB tables, old IAM roles. DO NOT recreate the DocumentDB IAM policy.
8. Delete legacy files (see Cleanup).
── Rollback at any step before 7 = point Route53 back at the old ALB.
```

## Failure modes

| Codepath | Realistic prod failure | Test? | Error handling? | User sees |
|----------|------------------------|-------|-----------------|-----------|
| ACM cert validation | DNS record not created → cdk deploy hangs | cdk synth only | CDK auto-creates Route53 validation record | deploy stalls (operator-visible) |
| `judge_assistants.json` build prereq | file missing → `docker build` fails (`Dockerfile:11`) | no | create.sh runs initialize_judges.py first | build error (operator) |
| `TABLE_PREFIX` not injected | app hits wrong/missing tables | **YES — regression test** | env default fallback | — |
| Multi-judge job on redeploy | daemon thread killed → row stuck `processing` | no (accepted) | **none** — documented caveat | **infinite spinner** ⚠ |
| DNS cutover propagation | brief split traffic old/new | manual | low TTL + keep old stack warm | none (both serve) |

**Critical gap (accepted, documented):** multi-judge job loss on redeploy is the
one failure that is silent AND has no error handling. Mitigated only by doc note
+ doing cutover during low traffic.

## NOT in scope (considered, deferred)

- **Move off Fargate** (App Runner / Lambda+SQS / Fly/Render) — explicitly rejected; staying on Fargate keeps the threading model intact.
- **React/S3 frontend split** (Nigel has it) — consensus stays server-rendered Flask; not needed.
- **Async job re-architecture** (SQS + worker Lambda) — rejected alongside the Lambda option.
- **DynamoDB history preservation / data migration** — chose fresh tables.
- **DynamoDB scan → GSI refactor** — pre-existing perf debt → TODO-1.
- **Full app test backfill** — → TODO-2; this PR ships the regression test only.
- **Secrets Manager migration** — keeping SSM Parameter Store.
- **Exact custom domain** — `APP_DOMAIN` config value, chosen at execution.

## Parallelization

| Lane | Modules touched | Depends on |
|------|-----------------|------------|
| A — CDK stack | `infra/` | — |
| B — app changes | `app.py`, `dynamodb_util.py`, `tests/`, `.dockerignore`, `Dockerfile` | — |
| C — op/admin scripts | `aws/`, `admin/` | A (stack outputs/STACK_NAME), B (TABLE_PREFIX contract) |
| D — docs + deletion | `docs/`, repo root | C |

Execution: **launch A ∥ B in parallel worktrees** (disjoint dirs, no conflict)
→ merge → **C** → **D**.
